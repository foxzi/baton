## [Unreleased]

### Добавлено

- Движок `codex` для шагов `agent:`: OpenAI Codex CLI запускается через
  `codex exec --json`, шлюз получает как MCP-сервер в собственном
  `config.toml`, а в границах политики шага его держит песочница самого CLI —
  отключить его shell нельзя. `skills` этот движок не поддерживает.
- Операция `create_issue` в паке `jira`: сценарий может через `tracker/v1` не
  только читать, но и заводить задачу.
- Параметр пака умеет адресовать вложенное поле тела запроса — путь на
  проводе задаётся через точки (`params.<name>.name: fields.summary`).
- `baton validate` сверяет сценарий с паками, которые тот загружает:
  операция должна существовать, её обязательные параметры — быть покрыты, а
  api с `readonly: true` можно вызывать только readonly-операциями.
- Шаг `switch` проверяется на полноту по enum схемы, из которой пришёл
  разбираемый ключ.
- Живые проверки за флагами окружения: `BATON_E2E_PROVIDERS=1` ходит в
  реальные LLM-провайдеры, `BATON_E2E=1` прогоняет агентский сценарий через
  установленный CLI `claude`. Обе цели запускает `make e2e`.
- CI валидирует каждый пак из `apis/` и каждый сценарий из `examples/`
  (`make validate-apis`, `make validate-examples`).

### Изменено

- Проверка записанного примера воспроизводит пагинацию: для операции с
  `paginate: true` пример — тело одной страницы, к нему применяется
  `pagination.items`, и трансформу подаются элементы этой страницы. Примеры
  пагинируемых операций `jira-server` перезаписаны как тела одной страницы.

### Исправлено

- Ключ кеша http-шага включает контрольную сумму пака, поэтому правка пака
  сама обесценивает записи, сделанные по старой версии.
- `ValidateJSON` разбирает числа как `float64` — исчезли ложные ошибки типа
  на целочисленных полях.
- `list_board_issues` в `jira-server` больше не теряет поле `description`.
- Секрет печатается как `***` и под числовыми глаголами форматирования: `%d`
  раньше проваливался к полям структуры и выводил открытое значение.

## [0.1.0] - 2026-09-09

Первый релиз: формат сценария, движок, API-паки и шлюз для агента.

### Добавлено

- **Формат сценария.** YAML с JSON Schema, типизированные входы и секреты,
  проверка выражений и шаблонов до запуска, статическая проверка ссылок между
  шагами. Шаги: `run`, `assert`, `http`, `llm`, `foreach`, `until`, `switch`,
  `agent`, `notify`, `file`.
- **Движок.** Каталог прогона с состоянием и логами, кеш результатов шагов,
  ретраи, которые не трогают отказы бюджета, политики и конфигурации, учёт
  стоимости обращений к модели и `baton resume <id>` для упавшего прогона.
- **Провайдеры.** Anthropic, OpenAI и OpenRouter для шагов `llm`: ответ по
  схеме и повтор при несоответствии схеме.
- **API-паки.** Загрузка из каталога или из git-источника с пином и
  контрольной суммой, конверты, пагинация `offset`/`cursor`/по заголовку
  `Link`, операции `form` и `graphql`, авторизация `exchange`, отказ на
  загрузке для нечистых jq-выражений.
- **Интерфейсы.** Реестр `forge/v1`, `tracker/v1`, `notify/v1`, проверка
  `implements` по записанным примерам и `interface:` в сценарии, чтобы пак
  выбирался входом.
- **Готовые паки.** `gitlab`, `github`, `gitea` (forge/v1), `jira`,
  `jira-server` (tracker/v1), `telegram`, `slack` (notify/v1) — у каждого
  README на английском и русском.
- **Агентские шаги.** Адаптер `claude-code` и MCP-шлюз, который отдаёт шагу
  только объявленные инструменты: команды, git, файлы, fetch, состояние и
  readonly-операции api, плюс проксирование сторонних MCP-серверов.
  Необъявленный инструмент отклоняется как нарушение политики.
- **CLI.** `run`, `resume`, `validate`, `runs list|show|logs`, `tools`,
  `schema`, `version` и `apis import|validate|call`.
- **Документация.** README, быстрый старт, обзор, ТЗ и сгенерированный
  справочник схемы на двух языках; примеры сценариев для ревью, отчётов и
  триажа.
- **Релиз.** goreleaser собирает статические бинарники для linux/amd64 и
  linux/arm64 с контрольными суммами, публикация — пушем тега `v*`.
