# Настройка редактора

Подключите JSON Schema сценария Baton к редактору, чтобы получить
автодополнение, подсказки и проверку имён, типов и обязательных полей во
время редактирования. Это не заменяет `baton validate`: семантические
проверки, например зависимостей шагов, по-прежнему требуют CLI.

## Что уже даёт `baton init`

`baton init` записывает `scenario.schema.json` — JSON Schema формата
сценария из этой же сборки (тот же документ, что печатает `baton schema`) —
рядом со сценарием, который он создаёт, и добавляет комментарий со схемой
первой строкой файла:

```yaml
# $schema: ./scenario.schema.json
```

Это форма комментария `$schema`, совместимая с IntelliJ, и
[yaml-language-server](https://github.com/redhat-developer/yaml-language-server)
(движок, стоящий за расширением YAML в VS Code, YAML-инструментами Neovim и
другими) поддерживает её напрямую, разрешая путь относительно файла
сценария, а не корня рабочей области. Больше ничего настраивать не нужно, и
доступ в сеть не требуется: схема — это обычный локальный файл,
сгенерированный тем же бинарником, которым вы запускали `init`, поэтому она
всегда совпадает с форматом, который этот бинарник реально разбирает.

Это покрывает:

- **VS Code** с установленным [расширением YAML](https://marketplace.visualstudio.com/items?itemName=redhat.vscode-yaml)
- **IDE на базе IntelliJ** (IntelliJ IDEA, GoLand, PyCharm, WebStorm, ...),
  встроенная поддержка JSON Schema в которых распознаёт комментарий
  `# $schema:` нативно
- **Neovim** через `yaml-language-server`, подключённый через
  `nvim-lspconfig` или похожий LSP-клиент
- Любой другой клиент `yaml-language-server`, так как он тоже принимает
  форму `# $schema:` наряду со своей собственной модлайн-записью
  `# yaml-language-server: $schema=...`

## Как направить редактор на сценарий, не созданный через `init`

У сценария, который не был создан через `init` — написанного вручную или
существовавшего до появления этой функции — нет ни `scenario.schema.json`
рядом, ни комментария со схемой. Есть два способа добавить валидацию:

**Добавить комментарий вручную.** Скопируйте `scenario.schema.json` из
сценария, уже созданного через `init` (или выполните
`baton schema > scenario.schema.json` в директории сценария), затем
добавьте первой строкой файла:

```yaml
# $schema: ./scenario.schema.json
```

Поправьте путь, если файл схемы лежит в другом месте относительно
сценария.

**Или настройте редактор вместо файла**, если не хочется добавлять строку в
каждый сценарий. В `settings.json` VS Code:

```json
{
  "yaml.schemas": {
    "./scenario.schema.json": ["hello.yaml", "summarize.yaml"]
  }
}
```

Ключ — это путь к схеме (или URL); значение — glob-шаблон, которому должны
соответствовать файлы сценариев. Полный список опций, включая настройки для
многокорневых рабочих областей и удалённых схем, смотрите в
[README yaml-language-server](https://github.com/redhat-developer/yaml-language-server#associating-schemas).

## Актуальность схемы

`scenario.schema.json` — это снимок: он отражает формат, понятный тому
бинарнику `baton`, который его записал, на момент записи. Если вы обновили
`baton` и формат с тех пор изменился, перегенерируйте файл:

```console
$ baton schema > scenario.schema.json
```

`init` не перезаписывает существующий `scenario.schema.json` (та же
гарантия «ничего не перезаписывается», которая действует для остальных
файлов, которые он создаёт), поэтому повторный запуск `init` в той же
директории не обновит его — используйте для этого `baton schema` напрямую.
