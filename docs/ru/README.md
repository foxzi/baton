# Baton

Headless-раннер сценариев на YAML, в которых чередуются **детерминированные** шаги (скрипты, HTTP-вызовы) и **недетерминированные** (вызовы LLM, кодинг-агенты). Один бинарник, один прогон на вызов, никакого UI и сервера. Аналог n8n для команд, которые предпочитают хранить сценарии как YAML в git и запускать их из CI или cron.

## Зачем

Задачи вида *собрать данные скриптом → отдать модели на интерпретацию → разложить результат и опубликовать его* обычно решаются одним из двух плохих способов: либо bash-обвязкой вокруг `claude -p` в каждом репозитории, которая не контролирует ни бюджет, ни безопасность, либо тяжёлой платформой с сервером, базой данных и веб-интерфейсом, что избыточно для одноразового прогона в CI. Baton закрывает этот промежуток: сценарий — это файл в репозитории, прогон — одна команда, а всё состояние прогона — каталог на диске.

## Ключевые возможности

- **Сценарии — это YAML в git.** Типизированные входы со значениями по умолчанию и паттернами, шаги с явными зависимостями, условия `when:` на expr-lang, статическая проверка ссылок: `baton validate` показывает все проблемы до того, как что-либо запустится, а `--dry-run` печатает план.
- **Девять типов шагов.** `run`, `http`, `llm`, `agent`, `foreach`, `until`, `file`, `switch`, `assert` — см. [таблицу ниже](#типы-шагов).
- **Вызовы модели с контрактом.** Anthropic, OpenAI и любой OpenAI-совместимый эндпоинт, включая OpenRouter. Каждый шаг `llm` возвращает JSON, провалидированный по схеме, с цепочкой запасных моделей и режимом structured output, согласованным под конкретного провайдера.
- **Кодинг-агент как один шаг.** Claude Code в v1, управляемый через встроенный шлюз MCP: раннер готовит workspace, отдаёт ровно те инструменты, которые разрешает профиль шага, и берёт ответ из `submit_result`.
- **Способность вместо доступа.** Ни shell, ни `curl`, ни доступа в сеть по умолчанию. Агент получает объявленные argv-команды с валидацией аргументов, запись файлов только внутри workspace с deny-списками путей, историю git и локальные коммиты, `fetch` по аллоулисту доменов, read-only операции паков, межпрогонное хранилище `state` и проксированные сторонние MCP-серверы. Набор выбирается профилем `review`, `fix` или `research`.
- **API-паки вместо встроенных интеграций.** HTTP-слой знает схемы авторизации (bearer, header, query, basic, обмен токена), пагинацию и трансформы на gojq; сервисы описываются YAML-паками, которые грузятся из каталога или из git с фиксацией версии и чексуммы. Паки реализуют `forge/v1`, `tracker/v1` и `notify/v1`, поэтому смена GitLab на GitHub — это входной параметр, а не переписывание.
- **Паки отлаживаемы.** `baton apis import` заводит пак из документа OpenAPI 3, `apis validate` прогоняет каждый записанный пример через конверт и трансформ, `apis call` вызывает одну операцию на живом сервисе.
- **Секреты, которых модель не видит.** Секрет — отдельный тип значения, подстановка секрета в промпт отклоняется на валидации, токены в вызовы API подставляет сам раннер, а все выводы, каталог прогона и кеш проходят через редактирование.
- **Бюджеты и учёт стоимости.** Лимиты по долларам, токенам, ходам агента и времени — на шаг и на прогон; реальная стоимость каждого вызова модели попадает в состояние прогона и в уведомления.
- **Классифицированные ошибки.** `transient`, `schema`, `command`, `timeout`, `budget`, `policy` и `config`, у каждого класса своя политика повторов — сбой `schema` повторяется с текстом ошибки валидации в контексте. `on_error: fail | continue | fallback`, порог `min_success` для `foreach`, `dedupe_key` для защиты побочных эффектов, `on_failure` на уровне прогона, который уведомляет всегда, и различимые коды выхода для CI.
- **Прогоны на диске, кеш и возобновление.** Каждый прогон — каталог `runs/<id>/` с состоянием, выводом шагов, логом событий в JSONL и аудит-логом каждого вызова инструмента агентом. Результаты шагов кешируются по хешу, поэтому повторный прогон не платит за токены заново, а `baton resume <id>` продолжает с упавшего шага.

## Как выглядит сценарий

```yaml
version: 1
name: code-review
description: Review a merge request, depth chosen by risk

inputs:
  project: { type: string, required: true, pattern: '^[\w.-]+/[\w.-]+$' }
  mr:      { type: int,    required: true }
  base:    { type: string, default: origin/main }

defaults:
  engine: claude-code
  model: anthropic/claude-sonnet-4-6
  timeout: 10m

budget:
  usd: 8
  time: 40m

steps:
  - id: diff
    run:
      argv: ["git", "diff", "{{ .inputs.base }}...HEAD"]

  - id: classify
    llm:
      model: anthropic/claude-haiku-4-5
      prompt: prompts/classify.md
      with: { diff: "{{ .steps.diff.stdout }}" }
      schema: schemas/classify.json

  - id: review
    when: 'steps.classify.result.risk != "low"'
    agent:
      prompt: prompts/review.md
      with: { project: "{{ .inputs.project }}", id: "{{ .inputs.mr }}" }
      profile: review
      max_turns: 25
      budget_usd: 2
      result: schemas/findings.json

  - id: publish
    http:
      op: forge.post_comment
      auth: forge_rw
      args:
        project: "{{ .inputs.project }}"
        id: "{{ .inputs.mr }}"
        body: "{{ render \"templates/review.md.tmpl\" .steps.review }}"
    dedupe_key: "review-{{ .inputs.project }}-{{ .inputs.mr }}"

  - id: gate
    assert: 'len(filter(steps.review.result.findings, .severity == "blocker")) == 0'

on_failure:
  - notify: telegram
    message: "{{ .run.name }} failed: {{ .run.error.class }} at {{ .run.failed_step }}"
```

Агент в шаге `review` может читать репозиторий и вызывать read-only операции форжа. Он не может опубликовать комментарий — для этого есть шаг `publish` с write-кредом, который модель никогда не видит.

## Типы шагов

| Шаг | Назначение |
|---|---|
| `run` | Выполнение команды через argv без shell, с захватом stdout/stderr и кода выхода |
| `http` | Вызов операции API-пака (`forge.post_comment`) или сырой запрос, креды из хранилища секретов |
| `llm` | Один вызов модели через Anthropic, OpenAI, OpenRouter или любой OpenAI-совместимый API, с обязательной схемой результата, цепочкой запасных моделей и опциональными инструментами |
| `agent` | Запуск CLI-агента (Claude Code в v1) с навыками, инструментами и MCP-серверами |
| `foreach` | Параллельная обработка списка с ограничением степени параллелизма и контролем частичного успеха |
| `until` | Ограниченный цикл с условием выхода, например «править, пока не пройдут тесты» |
| `file` | Чтение, запись и перечисление файлов в рабочей области |
| `switch` | Ветвление по значению выражения: по шагу на случай, синтаксический сахар над `when:` |
| `assert` | Намеренное падение прогона с отдельным кодом выхода, для блокировки merge в CI |

## Области применения

- **Код-ревью в CI.** Классифицировать изменение, выбрать глубину ревью, запустить read-only агента, опубликовать замечания отдельным шагом и заблокировать merge при блокерах. Один сценарий покрывает любой форж.
- **Периодические отчёты.** Cron обходит репозитории или системы, скрипты собирают данные, модель их обобщает, отчёт уходит в канал. Падение одного источника не роняет отчёт, но фиксируется в нём.
- **Триаж и классификация.** Классификация входящих тикетов по `enum`, диспетчеризация через `switch`, создание тикетов через `http`-шаги с write-кредами, которые модель не видит.
- **Автоматические исправления с проверкой.** Профиль `fix` позволяет агенту править workspace и запускать объявленные тестовые команды внутри ограниченного цикла `until`; результат — diff-артефакт, а его применение — отдельный шаг.
- **Регламентные проверки.** Детерминированные шаги собирают факты, LLM-шаг их интерпретирует, `assert` останавливает пайплайн при нарушении.

## Принципы

- **Раннер детерминирован, агентность — это шаг.** Baton исполняет DAG в предсказуемом порядке, а вся агентность инкапсулирована в шаге `agent:` или в шаге `llm:` с инструментами. Это делает прогоны воспроизводимыми, а бюджет — контролируемым.
- **Структурный контракт между шагами.** Каждый LLM-шаг возвращает JSON по схеме, а ветвление допускается только по провалидированным полям, в идеале — по `enum`.
- **Fail-fast по умолчанию, уведомление всегда.** Падение любого шага роняет прогон, если явно не указано иное, а `on_failure` выполняется для любого класса ошибки, включая исчерпание бюджета.
- **Триггеры снаружи.** Ни встроенного планировщика, ни вебхуков: используйте cron, systemd timer или расписание вашей CI. Именно это отличает CLI-инструмент от платформы.
- **Не платформа, не агент, не замена CI.** Нет веб-интерфейса, сервера и базы данных. Baton не решает, какие API вызывать, — это делает сценарий. Детерминированные сборки и тесты остаются в CI, Baton добавляет шаги, требующие интерпретации.

## Статус

**Запускается.** Шаги `run`, `assert`, `http`, `llm`, `foreach`, `notify`, `agent`, `until`, `file` и `switch` исполняются целиком, вместе с кешем, `resume`, бюджетами, `fallback`, `dedupe_key`, `fetch`, `state`, обработкой сигналов, шлюзом MCP с проксированием сторонних серверов, паками из git с проверкой интерфейсов и командами `baton apis`. [Пример недельного отчёта](../../examples/weekly-report.yaml) — текущий приёмочный сценарий: `foreach` по проектам через пак GitLab, дайджест от модели по JSON-схеме и уведомление, с кешем, так что повторный прогон той же недели не тратит токенов.

**Осталось.** Набор паков в `apis/`: здесь лежат паки `gitlab` и `telegram`, а любому другому сервису по-прежнему нужен свой пак. Полнота покрытия `switch` по `enum` схемы пока проверяется лишь предупреждением об отсутствии `default`, а не сверкой со значениями.

Дорожная карта по [техническому заданию](spec.md) (раздел 15):

## Сборка

Go, один статический бинарник, никаких внешних сервисов и базы данных. Требуется Go 1.25.7 или новее.

```sh
make build      # собирает ./baton с метаданными версии
make test       # go test ./...
make race       # go test -race ./...
make all        # fmt, vet, test, build
make docs       # пересобирает docs/{en,ru}/schema.md из схемы сценария
```

## Запуск

Если начинаете с нуля, [быстрый старт](quickstart.md) проводит через первый
прогон, оставленные им файлы и первый вызов модели.

```sh
baton validate examples/weekly-report.yaml
baton run examples/weekly-report.yaml \
    -i 'projects=["acme/web", "acme/api"]' -i since=2026-01-01
```

В `examples/` лежат сценарии, которые гоняют тесты: `hello.yaml`, `mr-comment.yaml`, `review.yaml`, `weekly-report.yaml`, `triage.yaml` и `llm-smoke.yaml`. Последнему не нужен ни форж, ни токен репозитория, только ключ провайдера: это самый короткий способ убедиться, что ключ, имя модели, режим structured output и учёт стоимости работают на живом сервисе:

```sh
export OPENROUTER_API_KEY=...
baton run examples/llm-smoke.yaml
```

Провайдер, каналы уведомлений и таблица цен живут в глобальной конфигурации: `~/.config/baton/config.yaml` или `./baton.yaml`, либо там, куда указывает `--config`. Секреты читаются из окружения или из файлов в момент, когда они нужны шагу.

Каждый прогон пишет `runs/<id>/`; прочитать это обратно можно через `baton runs list`, `runs show <id>` и `runs logs <id>`, а `baton resume <id>` продолжает упавший прогон. `--dry-run` печатает план, `--json` печатает события в JSONL, `--no-cache` игнорирует кеш, а `baton tools <scenario.yaml> --step ID` печатает инструменты, которые получит агент шага, ничего не выполняя. `baton apis import|validate|call` генерирует пак из документа OpenAPI 3, прогоняет его записанные примеры и вызывает одну операцию через запись `apis` сценария.
